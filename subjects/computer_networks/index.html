РОЗДІЛ 01

Вступ до комп'ютерних мереж

⬡ Що таке комп'ютерна мережа

Система, яка забезпечує зв'язок між двома чи більше комп'ютерами через дротове або бездротове середовище. Передача здійснюється електричними сигналами, світлом (оптоволокно) або радіохвилями.

⬡ 4 ключові характеристики мережі
  • Топологія — фізична організація вузлів (шина, зірка, кільце)
  • Протокол — набір правил передачі даних (TCP, IP, HTTP…)
  • Мережевий інтерфейс — програмно-апаратна межа між компонентами
  • Мережеве ПЗ — ОС і додатки для управління мережею

РОЗДІЛ 02

Принципи побудови мереж

⬡ Вимоги до глобальних мереж (WAN)
  • Масштабованість — зростання без втрати продуктивності
  • Надлишковість — резервні канали на випадок відмови
  • Безпека — брандмауери, шифрування, контроль доступу
  • Взаємодія — стандартні протоколи та інтерфейси
  • QoS — пріоритизація критичного трафіку
⬡ Технології WAN
MPLS
Багатопротокольна комутація міток — створює VPN між вузлами, пріоритизує трафік
VPN
Безпечне з'єднання через Інтернет із шифруванням
SD-WAN
Програмне управління WAN — інтелектуальна маршрутизація, зниження витрат
IXP
Точки обміну трафіком між ISP — зменшення затримки

Вита пара: Straight-through (ПК↔Switch) vs Crossover (ПК↔ПК, Switch↔Switch). Медіаконвертор — перетворює електричний сигнал ↔ оптичний.

⬡ Мережева карта (NIC)

Працює на фізичному рівні OSI. Має унікальну MAC-адресу (зберігається в ПЗП → копіюється в ОЗП при запуску). Кодує дані у електричні/оптичні сигнали. Зв'язується з ОС через драйвер пристрою. Підтримує: Gigabit/10G Ethernet, VLAN, QoS. Бездротова NIC — Wi-Fi адаптер (радіочастотні сигнали замість кабелю).

⬡ Типи серверів

Веб-сервер · Файловий · Бази даних · Додатків · Поштовий · DNS · Проксі · FTP · VoIP

⬡ Hub vs Switch — ключова різниця (Lab 2)

Collision domain — зона, де можуть виникати колізії. Hub = 1 великий collision domain. Switch = кожен порт ізольований. Broadcast domain — зона, де поширюються broadcast-кадри (обмежується маршрутизатором або VLAN).
⬡ Як комутатор будує таблицю MAC-адрес

1. Кадр надходить на порт → комутатор зчитує MAC джерела → записує в таблицю: MAC → порт.
2. Перевіряє MAC призначення у таблиці → якщо знайдено → пересилає на конкретний порт.
3. Якщо MAC призначення невідомий → пересилає на ВСІ порти (flooding), крім вхідного.
4. Записи в таблиці мають таймер старіння (зазвичай 300 сек).

Рівні 1–3 = мережозалежні (передача). Рівні 5–7 = програмно-орієнтовані (додатки). Рівень 4 = посередник.
⬡ Функції кожного рівня OSI
  • 1. Фізичний — біти → електричні/оптичні сигнали. Кабелі, роз'єми, кодування
  • 2. Канальний — фреймування, MAC-адресація, контроль помилок (CRC), CSMA/CD
  • 3. Мережевий — IP-адресація, маршрутизація, фрагментація пакетів
  • 4. Транспортний — надійна доставка (TCP), сегментація, контроль потоку
  • 5. Сеансовий — управління сеансами, синхронізація, контрольні точки
  • 6. Представлення — кодування (ASCII, UTF-8), шифрування (AES), стиснення
  • 7. Прикладний — HTTP, FTP, SMTP, DNS — інтерфейс до мережі для додатків

РОЗДІЛ 04

Ethernet та VLAN

⬡ Ethernet — основи

Найпопулярніший протокол LAN (IEEE 802.3), працює на рівнях 1 і 2 OSI. Канальний рівень поділяється на два підрівні:

  • LLC (Logical Link Control, IEEE 802.2) — інтерфейс з мережевим рівнем. Контроль потоку, помилок, мультиплексування протоколів. Режими: LLC1 (без з'єднання, без ACK), LLC2 (з з'єднанням, надійний), LLC3 (без з'єднання, з ACK)
  • MAC (Media Access Control) — інкапсуляція даних у кадри, MAC-адресація, контроль доступу до середовища (CSMA/CD). Реалізований в апаратурі (NIC)
⬡ CSMA/CD vs повний дуплекс

CSMA/CD (напівдуплекс): пристрій слухає лінію → передає → якщо колізія → JAM-сигнал → випадкова пауза → повтор. Використовувався в старих мережах зі спільним середовищем.

Сучасний Ethernet = повний дуплекс + комутатори → кожен пристрій має виділений канал до комутатора → колізії неможливі → CSMA/CD не потрібен.

⬡ Структура кадру Ethernet II (DIX)
Преамбула7 Б
SFD1 Б
MAC призн.6 Б
MAC джер.6 Б
Тип2 Б
Дані46–1500 Б
FCS (CRC)4 Б

Тип: 0x0800 = IPv4, 0x0806 = ARP, 0x86DD = IPv6. MTU = 1500 Б (Jumbo Frames до 9000 Б).

Мінімальний розмір кадру Ethernet = 64 байти (без преамбули/SFD). Якщо дані < 46 Б → додається padding (нулі). Мінімум потрібен для коректного виявлення колізій (CSMA/CD). FCS (CRC-32) обчислюється відправником, перевіряється отримувачем — якщо не збігається → кадр відкидається.
⬡ Типи MAC-розсилок
  • Unicast — один → один (конкретна MAC-адреса)
  • Broadcast — один → всі (FF:FF:FF:FF:FF:FF)
  • Multicast — один → група (починається з 01:00:5E)
⬡ VLAN (802.1Q)

Віртуальна LAN — логічна сегментація мережі на одному фізичному комутаторі. Кадри тегуються 4-байтовим тегом 802.1Q (VLAN ID 0–4095). Трафік між VLAN потребує маршрутизатора (L3).

⬡ Порти комутатора: Access vs Trunk (Lab 4)
Тип портуФункціяТегування
AccessПідключення кінцевих пристроїв (ПК, принтер)Належить одному VLAN, кадри без тегу
TrunkЗв'язок між комутаторами або з маршрутизаторомПередає кадри КІЛЬКОХ VLAN з тегами 802.1Q
Тег 802.1Q (4 байти) вставляється між MAC-джерела та полем Type у кадрі Ethernet. Містить VLAN ID (12 біт → 4096 VLAN) та пріоритет (3 біти).
⬡ Міжвланова маршрутизація (Lab 4)
  • Традиційна — окремий фізичний інтерфейс маршрутизатора для кожного VLAN (неефективно)
  • Router-on-a-Stick — один фізичний інтерфейс, поділений на субінтерфейси (GigabitEthernet0/0.10, .20). Кожен субінтерфейс = шлюз для свого VLAN. Порт комутатора до маршрутизатора = trunk
  • L3 Switch (SVI) — комутатор з маршрутизацією. Створюються віртуальні інтерфейси (interface vlan 10) — найшвидший метод
⬡ ARP — детальний процес (Lab 3)
Хост A хоче надіслати дані до хоста B (знає IP, не знає MAC):

1. A перевіряє ARP-кеш → немає запису
2. A надсилає ARP Request (broadcast FF:FF:FF:FF:FF:FF):
  "Хто має IP 192.168.1.5? Скажіть 192.168.1.1"
3. ВСІ пристрої отримують запит, тільки B відповідає
4. B надсилає ARP Reply (unicast) зі своєю MAC-адресою
5. A записує MAC B у ARP-кеш → передає дані
⬡ Структура MAC-адреси та OUI (Lab 3)
MAC: 00:1A:2B:3C:4D:5E
      ← OUI (виробник) → ← Серійний номер →

OUI (Organizationally Unique Identifier) — перші 3 байти (24 біти), призначені IEEE виробнику (Cisco, Intel, Dell...). Останні 3 байти — унікальний серійний номер пристрою.

РОЗДІЛ 05

Бездротова технологія Wi-Fi

⬡ Основи Wi-Fi (IEEE 802.11)

Бездротова LAN на основі радіохвиль. Використовує CSMA/CA (Collision Avoidance) замість CD — бо в радіо неможливо одночасно передавати і слухати колізії.

CSMA/CA: Прослуховування → Випадкова затримка → Передача → ACK від отримувача. Опціонально: RTS/CTS для уникнення проблеми "прихованого вузла".

⬡ Архітектура Wi-Fi
  • BSS (Basic Service Set) — одна точка доступу (AP) + клієнти
  • ESS (Extended Service Set) — кілька AP з одним SSID, роумінг
  • Ad-hoc (IBSS) — прямий зв'язок між пристроями без AP
⬡ Стандарти Wi-Fi

⬡ Проблеми бездротових мереж
  • Прихований вузол (Hidden Terminal) — вузли A і C не чують один одного, але обидва передають до B → колізія на B. Вирішення: RTS/CTS
  • Засвічений вузол (Exposed Terminal) — вузол C чує передачу B→A і помилково вважає канал зайнятим, хоча міг би передавати до D без перешкод
У бездротових мережах колізії неможливо виявити під час передачі (напівдуплекс радіо), тому замість CSMA/CD використовується CSMA/CA (Collision Avoidance).
⬡ CSMA/CA — детальний механізм
1. Прослуховування каналу (очікування DIFS)
2. Якщо канал вільний → випадкова затримка (backoff slots 0–15)
3. Лічильник = 0 → Передача кадру
4. Отримувач → ACK (підтвердження)
5. Немає ACK → подвоєння паузи → повтор (експоненційне зростання)

Опціонально (RTS/CTS):
Відправник → RTS (Request to Send) → Точка доступу
Точка доступу → CTS (Clear to Send) → Усі вузли
→ Усі інші вузли мовчать на вказаний час → Передача без колізій

RTS/CTS вирішує проблему прихованого вузла, але додає overhead. Використовується для великих кадрів.

⬡ Процес підключення до Wi-Fi (асоціація)
Етап 1 — Зондування (Probe)
Клієнт надсилає Probe Request на кількох каналах (з SSID або без)
Точки доступу відповідають Probe Response

Етап 2 — Автентифікація
Відкрита (Open/NULL) — ТД завжди погоджується
Із ключем (WEP — застаріле, WPA2/WPA3 — сучасне)

Етап 3 — Асоціація
Клієнт надсилає Association Request
ТД призначає AID (Association ID) = логічний порт
✓ Канал даних встановлено
⬡ Типи кадрів Wi-Fi (802.11)
  • Кадри даних (Data) — несуть корисне навантаження користувача

  • Без з'єднання — пакети незалежні, без попереднього handshake

⬡ Підмережі (Subnetting)
  • FLSM (Fixed Length) — усі підмережі однакового розміру
  • VLSM (Variable Length) — підмережі різного розміру (ефективніше)

⬡ NAT (Network Address Translation)

Перетворює приватні IP-адреси (10.x.x.x, 172.16–31.x.x, 192.168.x.x) у одну або кілька публічних для виходу в Інтернет. Основна причина — нестача IPv4 адрес.

⬡ IPv6-адресація

128 біт = 8 груп по 4 hex-цифри, розділених двокрапкою.

Повна: 2001:0db8:0000:0000:0000:0000:0000:0001
Правило 1 — провідні нулі в кожному блоці опускаються:
   → 2001:db8:0:0:0:0:0:1
Правило 2 — одна послідовність нулів замінюється на :: (тільки раз!):
   → 2001:db8::1
⬡ Типи IPv6-адрес

⬡ Таблиця степенів двійки (для розрахунків)
Біт:    7    6    5    4   3   2   1   0
Вага:  128   64   32   16   8   4   2   1

Приклад: 201 → 128+64+8+1 → 11001001
Приклад: 11101001 → 128+64+32+8+1 = 233

Макс. значення 8 біт: 11111111 = 255 (256 значень: 0–255)
Запам'ятай ключові маски: /24=256 адрес, /25=128, /26=64, /27=32, /28=16, /29=8, /30=4 (point-to-point), /31=2, /32=1
⬡ CIDR (безкласова адресація)

CIDR (Classless Inter-Domain Routing) — замінює жорсткі класи A/B/C. Довжина префікса /N визначає кількість бітів мережевої частини. Наприклад: 192.168.1.0/26 = маска 255.255.255.192 = 64 адреси (62 хости).

⬡ Wildcard mask (обернена маска)

Wildcard = NOT(маска). Показує, які біти IP-адреси можуть змінюватись. Використовується в ACL та протоколах маршрутизації (OSPF).

Маска:    255.255.255.0  = 11111111.11111111.11111111.00000000
Wildcard: 0.0.0.255      = 00000000.00000000.00000000.11111111

Правило: маска + wildcard = 255.255.255.255 (по кожному октету сума = 255)
⬡ Логічні операції в IP-адресації
AND — визначення мережевої адреси:
IP:    192.168.1.10  = 11000000.10101000.00000001.00001010
Маска: 255.255.255.0 = 11111111.11111111.11111111.00000000
AND:  192.168.1.0   = 11000000.10101000.00000001.00000000 ← мережа

NOT — інвертована маска (wildcard):
Маска: 255.255.255.0 → NOT → 0.0.0.255
Використовується в ACL та протоколах маршрутизації

OR — визначення broadcast-адреси:
Мережа:   192.168.1.0
Wildcard: 0.0.0.255
OR:       192.168.1.255 ← broadcast
Правила: 1 AND 1 = 1, решта = 0. NOT інвертує. 0 OR 0 = 0, решта = 1. Ці операції — основа для розрахунку підмереж на іспиті!
⬡ FLSM — приклад розрахунку

Мережа 192.168.1.0/24 → розбити на 4 підмережі.

Запозичуємо 2 біти з хост-частини: 2² = 4 підмережі, залишилось 6 біт → 2⁶ − 2 = 62 хости. Маска: /26 (255.255.255.192).

⬡ Порти
  • Добре відомі (0–1023): HTTP=80, HTTPS=443, FTP=21, SSH=22, DNS=53, SMTP=25
  • Зареєстровані (1024–49151): додатки (MySQL=3306, PostgreSQL=5432)
  • Динамічні (49152–65535): тимчасові, призначаються ОС клієнту
⬡ Функції транспортного рівня
  • Сегментація / збирання — великі дані розбиваються на сегменти для передачі, збираються на приймачі за sequence numbers
  • Мультиплексування — кілька додатків спільно використовують одне мережеве з'єднання через унікальні номери портів
  • Контроль потоку — регулювання швидкості передачі, щоб не перевантажити приймач (TCP sliding window)
  • Контроль помилок — виявлення втрачених/пошкоджених сегментів і повторна передача (TCP)
  • Керування з'єднаннями — встановлення (handshake), підтримка та завершення сеансів
⬡ Життєвий цикл TCP-з'єднання
▶ Встановлення (3-way handshake):
SYN → SYN+ACK → ACK

▶ Передача даних:
Кожен сегмент має Sequence Number
Отримувач надсилає ACK з номером наступного очікуваного байта
Якщо ACK не отримано → повторна передача (retransmission)

▶ Завершення (4-way teardown):
Клієнт → FIN → Сервер
Клієнт ← ACK ← Сервер
Клієнт ← FIN ← Сервер
Клієнт → ACK → Сервер
✗ З'єднання закрито
⬡ Контроль потоку та перевантаження (TCP)
  • Sliding Window — отримувач повідомляє розмір вікна (window size) у кожному ACK → відправник не надсилає більше даних, ніж вікно. Вікно = 0 → передача зупиняється
  • Контроль перевантаження — TCP починає з малого вікна (Slow Start), збільшує експоненційно до порогу, потім лінійно (Congestion Avoidance). При втраті пакета — зменшення вікна
⬡ Мультиплексування та демультиплексування

Мультиплексування (відправник): дані від кількох додатків (HTTP:80, SSH:22, DNS:53) збираються на транспортному рівні, кожен отримує заголовок з номером порту джерела та призначення.

Демультиплексування (отримувач): транспортний рівень читає порт призначення і направляє сегмент до правильного додатку. Сокет = IP + порт + протокол.

2. Server Hello + Certificate → (обраний алгоритм + сертифікат)
3. Клієнт перевіряє сертифікат, генерує session key
4. Key Exchange → обмін ключами
5. ✓ Шифрований канал встановлено
⬡ Cookies, кешування та TCP-сегментація (Lab 6)
  • Cookies — HTTP stateless → cookies зберігають стан між запитами (сесія, авторизація)
  • Кешування — браузер зберігає відповіді. Повторний запит → If-Modified-Since → сервер відповідає 304 (Not Modified) або новими даними
  • TCP-сегментація — великий HTTP-response (наприклад 4864 Б) не поміщається в один TCP-сегмент (MTU≈1460 Б). TCP розбиває на кілька сегментів → Wireshark: "TCP segment of a reassembled PDU"
РОЗДІЛ 10

Безпека мереж

⬡ Основні загрози
  • Malware — віруси, черв'яки, трояни, ransomware
  • Phishing — соціальна інженерія, підроблені сайти/листи
  • DDoS — перевантаження ресурсу масовими запитами
  • Man-in-the-Middle — перехоплення трафіку між сторонами
  • Spoofing — підробка IP/MAC/DNS адрес
  • SQL Injection, XSS — атаки на веб-додатки
⬡ Заходи безпеки
  • Брандмауер (Firewall) — фільтрація трафіку за правилами (IP, порти, протоколи). Типи: пакетний фільтр (L3-L4), stateful (відстежує з'єднання), Application-level (L7)
  • IDS / IPS — виявлення (IDS = пасивне) / запобігання (IPS = блокує) вторгненням. Аналіз сигнатур та аномалій
  • VPN — шифрований тунель через публічну мережу. Типи: Site-to-Site (з'єднання мереж), Remote Access (віддалені працівники). Протоколи: IPsec, OpenVPN, WireGuard
  • TLS/SSL — шифрування на транспортному рівні (HTTPS = HTTP + TLS). TLS Handshake → обмін ключами → шифрований канал
  • ACL (Access Control Lists) — правила на маршрутизаторах: дозволити/заборонити трафік за IP, портом, протоколом. Використовують wildcard mask
  • 802.1X — автентифікація на рівні порту комутатора (Supplicant → Authenticator → RADIUS-сервер)
  • IPsec — шифрування та автентифікація на мережевому рівні (L3). Режими: Transport (тільки дані) та Tunnel (весь пакет)

⬡ Нові тенденції
  • Zero Trust — ніколи не довіряй, завжди перевіряй
  • AI/ML у безпеці — автоматичне виявлення аномалій
  • SASE — об'єднання мережі та безпеки в хмарі
  • Мікросегментація — ізоляція трафіку всередині мережі
