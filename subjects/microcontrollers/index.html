Основні поняття

Мікропроцесор vs Мікроконтролер

Мікропроцесор (МП) — програмований пристрій, що виконує обробку даних згідно інструкцій у памʼяті. Потребує зовнішніх мікросхем (RAM, ROM, периферії), тому будується як мікропроцесорна система.

Мікроконтролер (МК) — «компʼютер-на-кристалі»: у єдиному кристалі інтегровані CPU, RAM, ROM (flash), порти вводу/виводу та периферія (таймери, АЦП, UART тощо). Призначений для однієї конкретної задачі; програма зберігається у ROM і, як правило, не змінюється.

ATmega32A та ядро AVR

Огляд моделі ATmega32A

ATmega32A — платформа Atmel, сімейство Mega, ядро AVR, архітектура RISC гарвардського типу. Це базова модель навчального курсу; лабораторні макети побудовані на ній або на старшій ATmega2560.

Корпуси: DIP-40, TQFP-44, QFN-44. Ноги портів мають альтернативні функції: наприклад, PA0–PA7 = ADC0–ADC7; PD0/PD1 = RxD/TxD (UART); PC6/PC7 = TOSC1/TOSC2 (кварц для асинхронного таймера) тощо.

Лабораторні макети. У курсових лабораторних роботах використовується старша модель ATmega2560 (Arduino Mega 2560) — те саме ядро AVR, але 256 КБ FLASH, 8 КБ SRAM, 11 портів (A, B, C, D, E, F, G, H, J, K, L), 4 UART, 16 каналів АЦП. Саме тому у завданнях зустрічаються ніжки PL, PK, PF, яких немає у ATmega32A. Детальніше — Розділ 8.

Структура ядра AVR

Ядро AVR — гарвардської архітектури: фізично розділені пам'ять програм (FLASH) та пам'ять даних (SRAM), кожна з власною шиною. Команди витягуються з FLASH паралельно з доступом до SRAM, що забезпечує високу швидкість.

Ключові елементи ядра:

  • 32 регістри загального призначення (R0–R31) — безпосередньо підключені до АЛП, доступ за 1 такт
  • Програмний лічильник (PC) — вказує на наступну команду у FLASH
  • Вказівник стеку (SP) — для підпрограм і переривань; стек розміщується у SRAM
  • Регістр стану SREG — прапорці C/Z/N/V/S/H/T/I після арифметичних та логічних операцій
  • АЛП — виконує арифметичні, логічні, зсувні операції
  • Периферія — I/O порти, таймери, USART, TWI (I²C), SPI, АЦП
Переносимість коду. Ядро AVR однакове у всіх моделях сімейства — від ATtiny до ATmega. Це робить переносимість коду в межах лінійки дуже простою; відрізняється лише склад периферії та обсяги пам'яті.

Організація памʼяті даних

Адресація у SRAM побайтна, лінійна, без поділу на сегменти/банки. Регістри загального призначення, регістри вводу/виводу та внутрішня SRAM знаходяться в одному адресному просторі — це відрізняє AVR від класичних архітектур.

Адресний простір пам'яті даних AVR: ┌──────────────────────────────────────────────────┐ │ $0000 │ R0 │ 32 регістри загального │ │ … │ … │ призначення (R0–R31). │ │ $001F │ R31 │ Доступ за іменами R0…R31 │ │ │ │ або через LOAD/STORE. │ ├──────────────────────────────────────────────────┤ │ $0020 │ I/O │ 64 регістри вводу/виводу: │ │ … │ $00 │ порти, таймери, АЦП, USART, │ │ $005F │ $3F │ SPI, TWI, керування. │ │ │ │ Швидкі IN/OUT: тільки $00–$1F. │ │ │ │ SBI/CBI, SBIS/SBIC: лише $00– │ │ │ │ $1F (молодші 32 I/O). │ ├──────────────────────────────────────────────────┤ │ $0060 │ │ Внутрішня SRAM. │ │ … │ │ Дані користувача починаються │ │ RAMEND │ │ з адреси $0060. │ └──────────────────────────────────────────────────┘ Приклад для ATmega32A (SRAM = 2 Кбайт = 0x800): RAMEND = 0x1F + 0x3F + 0x800 = 0x85F
Формула RAMEND: RAMEND = 0x1F (регістри заг. призн.) + 0x3F (I/O регістри) + обсяг SRAM.
У «нафаршированих» моделях після $005F резервується додаткова область $0060–$00FF для ще 160 I/O-регістрів (тільки через LOAD/STORE; SBI/CBI до них не працюють). Тоді SRAM починається з $0100.

Режими сну (Sleep Modes)

Для зниження енергоспоживання (акумуляторні пристрої, датчики на батарейках) AVR підтримує шість режимів сну. Різниця — які модулі залишаються активними, а які зупиняються. Режим вибирається бітами SM2:0 у регістрі MCUCR; перехід у режим — команда SLEEP після встановлення SE=1 у MCUCR.

Типова стратегія low-power:
  1. Налаштувати WDT на інтервал 8 сек у режимі переривання
  2. У WDT ISR — прокидатися, знімати вибірку датчика, можливо передавати по UART, заснути знову
  3. Середнє споживання 1 мкА · 99% + 10 мА · 1% = 100 мкА → роки роботи від CR2032

Фьюзи (fuse bits) — конфігурація при програмуванні

Fuse bits — окремий набір бітів конфігурації МК, що зберігаються в окремій області (не у FLASH, не у EEPROM) і записуються лише програматором (ICSP або JTAG), а не самою програмою користувача. Визначають фундаментальні апаратні параметри: джерело тактового сигналу, розмір bootloader, BOD-поріг, дозвіл налагодження тощо.

У ATmega32A/ATmega2560 є три групи fuse: Low Fuse, High Fuse, Extended Fuse — по 8 біт кожен.

Програмування AVR мовою асемблер

Структура асемблерної програми

Асемблерна програма для AVR поділена на сегменти за допомогою директив. Три основні сегменти:

  • .CSEG — сегмент коду (розміщується у FLASH)
  • .DSEG — сегмент даних (розміщується у SRAM)
  • .ESEG — сегмент EEPROM
; Типова програма для ATmega32A .include "m32Adef.inc" ; підключення бібліотеки з іменами регістрів .DSEG ; сегмент SRAM counter: .byte 1 ; зарезервувати 1 байт для змінної .CSEG ; сегмент FLASH (код) .org $000 ; адреса початку програми (reset vector) jmp RESET ; перехід на основну програму .org $002 jmp EXT_INT0 ; вектор переривання INT0 ; ... інші вектори RESET: ; початок виконання після скидання ldi R16, high(RAMEND) out SPH, R16 ; ініціалізація вказівника стеку ldi R16, low(RAMEND) out SPL, R16 ldi R16, 0xFF ; налаштувати порт A на вихід out DDRA, R16 MAIN_LOOP: ; основна програма rjmp MAIN_LOOP ; нескінченний цикл

Стек — область SRAM, де зберігаються адреси повернення з підпрограм/переривань та тимчасові дані. Вказівник стеку SP (SPH:SPL) вказує на вершину стеку; зростає від RAMEND у бік менших адрес.

; Обов'язкова ініціалізація стеку на початку програми: ldi R16, high(RAMEND) out SPH, R16 ldi R16, low(RAMEND) out SPL, R16 ; Виклик підпрограми: rcall MY_SUB ; R24/R25 ← поточна адреса + 1, збережена у стеку ; ... повертаємось сюди MY_SUB: push R16 ; зберегти регістр на стеку push R17 ; ... робота підпрограми pop R17 ; відновити (у зворотному порядку!) pop R16 ret ; витягнути адресу зі стеку, перейти
Правило PUSH/POP: завжди парні, у зворотному порядку. Якщо підпрограма змінює SREG, його теж треба зберігати: in R0, SREG / push R0.

Макроси

Макрос — іменований шаблон коду, що розгортається при кожному виклику. На відміну від підпрограми, макрос не економить пам'ять FLASH, але економить час (немає накладних витрат CALL/RET) та підвищує читабельність.

; Визначення макросу .macro SET_OUT ; SET_OUT port, pin sbi DDR@0, @1 ; @0, @1 — параметри макросу .endmacro ; Використання: SET_OUT A, 3 ; розгорнеться у: sbi DDRA, 3 SET_OUT B, 7 ; розгорнеться у: sbi DDRB, 7

Високоімпедансний стан (Hi-Z) та синхронізація PINx

Коли вивід налаштований на вхід без підтяжки (DDRxn=0, PORTxn=0), він перебуває у стані Hi-Z (High-Impedance). Вхідний опір — дуже високий (фактично розімкнутий), тому вивід «не заважає» іншим пристроям на спільній шині. Це використовується для:

  • Підключення до спільних шин даних з іншими МК або пристроями (один говорить — решта у Hi-Z)
  • Пасивного прослуховування сигналу без навантаження джерела
  • Зменшення споживання при неактивних виводах
Плаваючий вхід. Hi-Z-вхід дуже чутливий до наводок: навіть дотик пальця до корпусу МК може дати «1». Якщо вхід не буде задіяний — або додавайте підтяжку (PORTxn = 1), або завжди конфігуруйте на вихід.

Синхронізація PINx. Між командою запису в PORTx (або появою сигналу на фізичній нозі) та моментом, коли це відобразиться у PINx, існує затримка — приблизно ½ такту системного годинника. Внутрішній ланцюг захоплення значення синхронізується з тактовим сигналом через заскочку. На практиці:

Підключення кнопок та світлодіодів

Дві типові схеми підключення кнопки:

Два способи підключення LED до ноги МК:

  • Активна «1» (sourcing): нога → резистор → LED → GND. LED світиться, коли на нозі високий рівень.
  • Активна «0» (sinking): Vcc → резистор → LED → нога. LED світиться, коли на нозі низький рівень. Переважний варіант: AVR може «поглинати» більший струм, ніж видавати.

Програмне «брязкання» кнопок (debouncing)

При натисканні механічної кнопки контакти декілька мс «дриґають» — генерують серію перемикань «1»↔«0», що МК сприймає як кілька натискань. Усунення — дебаунсинг:

  1. Виявити зміну рівня.
  2. Зачекати 10–50 мс (програмна затримка або таймер).
  3. Перевірити рівень повторно. Якщо стабільний — вважати натиском.
  4. Дочекатися відпускання (та знову затримка), щоб уникнути множинних спрацювань при одному натиску.

Переривання та пам'ять

Механізм переривань

Переривання (interrupt) — реакція МК на подію від периферії (таймер, UART, АЦП, зовнішній сигнал). При настанні події виконання основної програми призупиняється, виконується підпрограма обробки (ISR), далі — повернення до перерваної команди.

Послідовність дій при виникненні переривання:

  1. Периферія виставляє прапор переривання у відповідному регістрі (наприклад TIFR.TOV0 при переповненні T0).
  2. МК завершує поточну команду.
  3. Адреса наступної команди заноситься у стек.
  4. Прапор переривання автоматично скидається.
  5. Перехід на адресу вектора переривання у таблиці векторів.
  6. У таблиці — команда jmp/rjmp на ISR.
  7. ISR завершується командою RETI (відновлює адресу зі стеку + знову встановлює I у SREG).
Три обов'язкові умови для спрацювання переривання:
  1. Активізована периферія (напр., увімкнено таймер).
  2. Локальний дозвіл для цієї події (напр., TIMSK.TOIE0 = 1).
  3. Загальний дозвіл: біт I у SREG = 1 (команда SEI; заборона — CLI).

Робота з SRAM, FLASH, EEPROM

SRAM — звичайна пам'ять даних. У асемблері — LD/ST, у C — просто звичайні змінні. Для адресації використовуються непрямі регістри X (R26:R27), Y (R28:R29), Z (R30:R31).

FLASH — пам'ять програм. Константні таблиці (повідомлення, звукові ноти) розміщуються тут, щоб не витрачати цінну SRAM. Читання — тільки через команду LPM (Load from Program Memory) з використанням регістра Z.

EEPROM — пам'ять, що зберігається при вимкненні живлення. Доступ побайтно через регістри EEAR (адреса), EEDR (дані), EECR (керування). Запис значно повільніший за читання (~8.5 мс на байт) і має обмежений ресурс ~100 000 циклів на комірку.

Вкладені переривання та біт I

При вході в ISR, AVR автоматично скидає біт I у SREG — глобальний дозвіл переривань вимикається. Це означає: за замовчуванням ISR не переривається іншими ISR. Команда RETI (на відміну від звичайної RET) повертає I назад у 1 при виході.

Основна програма [I=1] ─┐ │ INT0 подія ▼ ISR(EXT_INT0) [I=0 ← автоматично] // інші переривання заблоковані // якщо тут виставляється TIMER0_OVF — прапор зберігається reti │ [I=1 ← RETI відновлює] │ Основна програма [I=1] ─┤ │ одразу ж — виставлений раніше прапор ▼ ISR(TIMER0_OVF) [I=0] reti │ [I=1] Основна програма [I=1] ─┘

Якщо потрібно дозволити вкладені переривання (наприклад, критичний UART-RX не має чекати на повільну ISR), можна вручну відновити I усередині ISR:

ISR(TIMER0_OVF_vect) { sei(); // вручну дозволити переривання // … довга обробка, що може бути перервана вищими за пріоритетом ISR // I все одно відновиться через RETI при виході }
Обережно з вкладеннями. Якщо всередині ISR зроблено sei(), а потім повторно виникає та ж подія — буде рекурсивний виклик ISR → стек переповниться. Використовуйте лише для швидкого делегування критичних перериваннь, у яких не може бути повторного входу.

Читання з FLASH у асемблері — команда LPM

Для доступу до констант у пам'яті програм з асемблера використовується команда LPM (Load from Program Memory). Адреса завантажується в регістр Z, результат — у R0.

ВАРІАНТДІЯ
lpmR0 ← FLASH[Z]
lpm Rd, ZRd ← FLASH[Z]
lpm Rd, Z+Rd ← FLASH[Z]; потім Z++
Важливо про адресацію FLASH. FLASH адресується послівно (по 2 байти), але LPM читає побайтно. Молодший біт Z обирає, який байт слова читати (0 = молодший, 1 = старший). При розміщенні масиву через .db у CSEG два байти пакуються в одне слово — саме тому побайтне читання можливе.

EEPROM: протокол запису з 4-тактовим вікном

Запис у EEPROM — повільний (~8.5 мс на байт) і критичний до послідовності. Апаратура вимагає точного дотримання протоколу для захисту від випадкових записів (при скиданні живлення, наприклад).

РЕГІСТРПРИЗНАЧЕННЯ

Послідовність запису (точно у такому порядку!):

Крок 1: Чекати, поки EEWE=0 (попередній запис завершився) Крок 2: Завантажити адресу в EEAR, дані в EEDR Крок 3: Встановити EEMWE=1 (Master Write Enable) — це «дозвіл на дозвіл» Крок 4: ПРОТЯГОМ 4 ТАКТІВ встановити EEWE=1 — запис почнеться Якщо затриматись — EEMWE апаратно скинеться, запис не відбудеться // C (avr-libc): void eeprom_write(uint16_t addr, uint8_t data) { while (EECR & (1 << EEWE)); // крок 1 EEAR = addr; // крок 2 EEDR = data; EECR |= (1 << EEMWE); // крок 3 EECR |= (1 << EEWE); // крок 4 — має виконатись швидко } // Або просто: #include <avr/eeprom.h> eeprom_write_byte((uint8_t*)addr, data); // бібліотека робить все коректно
Чому два біти? EEMWE (Master Write Enable) — «дозвіл на дозвіл» — автоматично скидається через 4 такти після встановлення. EEWE (Write Enable) — «власне запис» — діє лише якщо EEMWE ще 1. Ця «вікно з 4 тактів» запобігає випадковому запису при помилках програми або нестабільному живленні.

Читання простіше: завантажити адресу → встановити EERE=1 → через 4 такти забрати байт з EEDR.

Безпечне читання 16-бітних периферійних регістрів

Такі регістри як TCNT1, OCR1A, ICR1, ADC, EEAR — 16-бітні, але шина даних AVR — 8-бітна. Апаратура використовує буферний регістр старшого байта, щоб читання/запис двох байтів було атомарним.

Правило:

  • Читання: спершу TCNT1L (молодший) → старший байт автоматично защіпається у TEMP-регістрі → потім TCNT1H читає з TEMP.
  • Запис: спершу TCNT1H (у TEMP) → потім TCNT1L — у цей момент обидва байти атомарно записуються.
; НЕПРАВИЛЬНО — може статися зміна TCNT1 між читаннями: in r16, TCNT1H in r17, TCNT1L ; ← TCNT1 міг збільшитись між цими командами! ; ПРАВИЛЬНО: in r17, TCNT1L ; L читається першим; H автоматично у TEMP in r16, TCNT1H ; H читається з TEMP (значення 16-бітне атомарне) ; У C avr-libc робить це автоматично: uint16_t cnt = TCNT1; // компілятор згенерує правильну послідовність
Для ADC: правило протилежне — спершу ADCL, потім ADCH. Читання ADCL блокує доступ до ADCH, поки той не буде прочитаний. У avr-libc uint16_t r = ADC; виконує цей порядок автоматично.
В ISR. Якщо основний код читає 16-бітний регістр не в один машинний цикл, потрібно захистити читання від переривань — обгорнути cli() / sei() або використати макрос ATOMIC_BLOCK() з <util/atomic.h>. Інакше ISR, що змінює цей регістр, може призвести до нестабільного значення.

Застосування: керування яскравістю LED, швидкістю DC-моторів, сервоприводами, «цифро-аналогове перетворення».

Приклад: при FCPU = 8 МГц і prescaler = 1, Fast PWM = 31 250 Гц; Phase Correct = 15 686 Гц.

Логіка виведення на OCn: у Fast PWM на початку циклу вивід встановлюється в «1», при співпадінні TCNT = OCR — скидається в «0». У Phase Correct — два співпадіння за період (при висхідному та спадному рахунку), що дає симетричний імпульс. Інверсний режим — навпаки.

Подвійна буферизація OCR. Щоб уникнути несиметричних імпульсів при зміні шпаруватості на льоту, запис у OCRn насправді йде у буферний регістр, а оновлення відбувається лише при досягненні TCNT значення 255 (BOTTOM/TOP). Для програмного коду це прозоро — просто «записав OCR, новий duty застосується зі старту наступного періоду».

Крайні випадки OCR:

  • OCR = 0 — у Fast PWM кожні 256+1 тактів буде короткий імпульс (може спричинити блимання); краще взагалі відключити OCn від таймера.
  • OCR = 255 — вивід OCn перебуває у стійкому стані («1» або «0»), не блимає.
Біт FOC (Force Output Compare). Запис «1» у розряд FOCn регістра TCCRn примусово міняє стан виводу OCn (як ніби відбулося співпадіння), не генеруючи переривання. Корисно для синхронізації кількох каналів PWM або зупинки PWM у визначеному стані.

Сторожовий таймер (WatchDog)

WDT — незалежний таймер на власному осциляторі (~1 МГц у AVR). Призначення: якщо основна програма «зависла», WDT через заданий час (15 мс – 2 сек) автоматично скидає МК.

↪ WDT також продовжує працювати у всіх sleep-режимах і може бути джерелом пробудження — див. Розділ 2, «Режими сну».

Програмне подовження інтервалів таймера (патерн «25 мс × N»)

8-бітний таймер має обмежений максимальний інтервал: при FCPU=8 МГц і prescaler=1024 переповнення настає щойно через 32.768 мс. Як відрахувати 1 секунду? Використати програмний лічильник переривань у ISR.

Патерн (з textbook): налаштуйте таймер на короткий стабільний інтервал (наприклад 25 мс у режимі CTC), а у ISR інкрементуйте змінну; коли вона досягне потрібного числа — виконайте дію і обнуліть.

// F_CPU = 8 МГц, prescaler = 1024, OCR = 0xC2 → T = 25 мс volatile uint8_t cnt = 0; volatile uint8_t flag = 0; // 0 = ще рахуємо, 1 = пора блимнути // Налаштування T0: CTC, prescaler=1024 void init_t0(void) { TCCR0 = (1 << WGM01) // CTC-режим | (1 << CS02) | (1 << CS00); // prescaler=1024 OCR0 = 0xC2; // ≈ 25 мс TIMSK |= (1 << OCIE0); // дозвіл compare sei(); } ISR(TIMER0_COMP_vect) { cnt++; if (cnt >= 40) { // 40 × 25 мс = 1 сек cnt = 0; flag = 1; } } int main(void) { DDRC |= (1 << 5); init_t0(); while (1) { if (flag) { flag = 0; PORTC ^= (1 << 5); // блимнути LED } // інша робота не блокується } }
Перевага над delay(): основна програма не блокується, може одночасно виконувати кілька незалежних задач (див. приклад з textbook: один таймер обслуговує і блимання LED, і дебаунсинг кнопки, і зумер — кожна задача має свій прапорець і свій лічильник у ISR).

Синхронізація асинхронного T2 (регістр ASSR)

При роботі T2 від окремого кварцу 32 768 Гц, CPU (clkI/O) та таймер (clkT2S) працюють у різних тактових доменах. Запис у регістри T2 із основного коду — не миттєвий, бо значення має бути синхронізовано з повільним clkT2S.

// Безпечне переналаштування асинхронного T2 void set_async_timer(uint8_t new_ocr) { // Чекати, поки попередні записи синхронізувалися while (ASSR & ((1 << TCN2UB) | (1 << OCR2UB) | (1 << TCR2UB))); OCR2 = new_ocr; // новий запис // Почекати синхронізації while (ASSR & (1 << OCR2UB)); }
Типова послідовність старту RTC на T2:
1. Записати 0 у TIMSK (відключити переривання T2).
2. Встановити AS2 = 1 у ASSR.
3. Записати TCNT2, OCR2, TCCR2.
4. Чекати, поки всі UB-біти скинуться.
5. Скинути TIFR (можуть бути фальшиві прапори).
6. Дозволити переривання у TIMSK.
Порушення порядку → непередбачувана поведінка при першому запуску.

Динамічна індикація 7-сегментників (Lab 4)

При підключенні 6 семисегментних індикаторів напряму потрібно 6×8 = 48 виводів МК — це забагато. Рішення — динамічна індикація: всі індикатори мають спільну шину сегментів (8 виводів), а живляться по черзі через транзисторні ключі на виводах керування (6 виводів). LCD HD44780 + клавіатура 4×4 (Lab 3)

HD44780 — стандартний контролер символьних LCD-дисплеїв (1–4 рядки × 8–40 символів). Два режими інтерфейсу: 8-біт (D0–D7, всі дані за один strobe E) та 4-біт (D4–D7, байт передається двома ніблами — економія на 4 виводи МК).

Керуючі сигнали: RS (Register Select: 0=команда, 1=дані), RW (0=запис, 1=читання; часто прив'язаний до GND), E (Enable — строб по спадаючому фронту).

Сканування клавіатури 4×4: 4 виводи підключені до рядків (на вихід), 4 — до стовпців (на вхід з підтяжкою). По черзі «опускаємо в 0» кожен рядок, читаємо стовпці — якщо якийсь у 0, це натиснута клавіша.

Директива volatile

Змінні, що змінюються поза межами основного потоку (у ISR або апаратно), повинні оголошуватися з ключовим словом volatile. Інакше оптимізатор може кешувати значення у регістрі й не перечитувати його з пам'яті.

volatile uint8_t flag = 0; // змінюється в ISR ISR(INT0_vect) { flag = 1; // сигнал з переривання } int main(void) { while (!flag); // без volatile цей цикл став би // `while(1);` після оптимізації! // ... обробка події }
Правила: volatile обов'язковий для (1) змінних, модифікованих у ISR і читаних у main, (2) покажчиків на регістри периферії, (3) змінних, доступних через DMA.

Програмні затримки

Бібліотека <util/delay.h> надає функції блокуючої затримки, реалізовані через цикли NOP. Точність залежить від коректності F_CPU.

#define F_CPU 16000000UL #include <util/delay.h> _delay_ms(100); // затримка 100 мс _delay_us(50); // затримка 50 мкс // Обмеження: // _delay_ms — максимум 262.14 мс / F_CPU (МГц) // _delay_us — максимум 768 мкс / F_CPU (МГц)
Недоліки програмних затримок: блокують CPU, неточні при перериваннях, погано масштабуються. Для точних і неблокуючих інтервалів — використовуйте таймери + ISR.

millis() та неблокуючі затримки

millis() повертає 32-бітне число мілісекунд від старту скетчу. Arduino Core тримає його через ISR на Timer0 (prescaler=64, overflow ~1.024 мс), тому Timer0 зайнятий системою — не використовуйте його для власних цілей у Arduino-скетчах. Використовуйте T1, T2, T3–T5.

// Блимання без блокування — неможливо з delay(), легко з millis(): const uint8_t LED = 13; unsigned long prevMs = 0; const unsigned long INTERVAL = 500; bool state = false; void loop() { unsigned long now = millis(); if (now - prevMs >= INTERVAL) { prevMs = now; state = !state; digitalWrite(LED, state); } // тут можна робити інші речі — цикл не блокується! }
Переповнення millis(): unsigned long = 32 біти = ~49.7 днів. Коректний патерн — if (now - prev >= INTERVAL) — працює навіть через перехід через 0 (беззнакова арифметика). Ніколи не пишіть if (now >= prev + INTERVAL) — це зламається при переповненні.

UART vs USART

UART (Universal Asynchronous Receiver/Transmitter) — асинхронний послідовний інтерфейс без окремої лінії синхронізації; синхронізація з бітової швидкості (baud rate), узгодженої заздалегідь.

USART — те саме + синхронний режим (з окремою лінією XCK). Модуль у AVR — USART; у більшості завдань використовують лише асинхронну частину.

Baud rate (бод) — кількість символів (біт, у простому випадку) за секунду. Типові значення: 1200, 2400, 4800, 9600, 14400, 19200, 38400, 57600, 115200 бод.

Розрахунок регістра UBRR для асинхронного режиму (U2X=0): UBRR = F_CPU / (16 · baud) − 1 Приклад: F_CPU = 16 МГц, baud = 9600 UBRR = 16 000 000 / (16 · 9600) − 1 = 103,17 − 1 ≈ 103 Похибка бодрейту: ((16·(UBRR+1)·baud) / F_CPU − 1) · 100% Для 103 → baud_факт = 16 МГц / (16·104) = 9615,4 бод Похибка = (9615,4 − 9600) / 9600 · 100% ≈ +0,16% (допустима: ≤2%) // Налаштування у коді (ATmega32A): #define BAUD 9600 #define UBRR_V ((F_CPU / 16UL / BAUD) - 1) UBRRH = UBRR_V >> 8; UBRRL = UBRR_V & 0xFF; UCSRB = (1 << RXEN) | (1 << TXEN); // enable RX+TX UCSRC = (1 << URSEL) | (3 << UCSZ0); // 8 data bits, no parity, 1 stop

Подвійна швидкість — біт U2X. Запис U2X=1 у UCSRA подвоює ефективну швидкість при тому ж UBRR, змінюючи формулу:

Режим U2X=1 (double speed): UBRR = F_CPU / (8 · baud) − 1 Дозволяє досягти вищих baud rate на фіксованій F_CPU, але знижує запас на фазовий джиттер (приймач семплить кадр 8 разів замість 16 — чутливіше до неточностей).

9-бітний режим передачі (TXB8 / RXB8)

UART AVR підтримує кадр з 9 біт даних. 9-й біт знаходиться поза регістром UDR і керується через UCSRB: TXB8 (біт 0) для передачі, RXB8 (біт 1) для прийому.

// Налаштування 9-бітного режиму: UCSRB = (1 << RXEN) | (1 << TXEN) | (1 << UCSZ2); UCSRC = (1 << URSEL) | (1 << UCSZ1) | (1 << UCSZ0); // UCSZ2:0 = 111 → 9 біт даних // Передача 9-бітного значення: void uart_send_9(uint16_t data) { while (!(UCSRA & (1 << UDRE))); if (data & 0x100) UCSRB |= (1 << TXB8); // встановити 9-й біт else UCSRB &= ~(1 << TXB8); // скинути UDR = data & 0xFF; // молодші 8 біт } // Прийом 9-бітного значення: uint16_t uart_recv_9(void) { while (!(UCSRA & (1 << RXC))); uint16_t bit9 = (UCSRB & (1 << RXB8)) ? 0x100 : 0; return bit9 | UDR; // СПЕРШУ RXB8, потім UDR! }
Порядок при прийомі важливий: RXB8 діє для наступного байта в буфері, тому читайте його до UDR. Читання UDR просуває чергу приймача — ви втратите RXB8 для поточного байта.

Практичне використання: адресний маркер у мультипроцесорній мережі (9-й біт = 1 → адреса, 9-й біт = 0 → дані). Саме цей механізм лежить в основі Lab 8 RS-485.

FIFO кільцевий буфер

Щоб ISR передавала дані не блокуючи основний код — використовують кільцевий буфер (FIFO) на стороні TX та RX. ISR забирає / кладе один байт, основний код працює через черги.

#define BUF_SIZE 64 volatile uint8_t rxBuf[BUF_SIZE]; volatile uint8_t rxHead = 0, rxTail = 0; ISR(USART_RXC_vect) { uint8_t next = (rxHead + 1) % BUF_SIZE; if (next != rxTail) { // буфер не повний rxBuf[rxHead] = UDR; rxHead = next; } else { (void)UDR; // переповнення: скинути байт } } int16_t uart_getchar(void) { // −1 якщо буфер порожній if (rxHead == rxTail) return -1; uint8_t c = rxBuf[rxTail]; rxTail = (rxTail + 1) % BUF_SIZE; return c; }

  • Без handshake — лише TxD/RxD/GND. Приймач просто має встигати обробляти; якщо ні — переповнення.

RS-485 — диференціальна передача

RS-485 (EIA/TIA-485) — найпоширеніший стандарт промислового зв'язку. Обмін між кількома пристроями (до 32) по одній двопровідній лінії у напівдуплексному режимі на великі відстані.

Принцип: диференціальна передача. По дроту A — прямий сигнал, по B — інверсний. Приймач реагує на різницю A−B, завдяки чому синфазні завади (що діють на обидва дроти) нейтралізуються.

Виводи MAX485: RO (вихід приймача → RxD МК), DI (вхід передавача ← TxD МК), DE (дозвіл передавача), RE̅ (дозвіл приймача, активний «0»), A та B (лінія).

Напівдуплекс: у кожен момент часу або приймаємо (DE=0, RE̅=0), або передаємо (DE=1, RE̅=1). Переключення через спільну ногу МК: DE і RE̅ часто з'єднують. Після передачі обов'язково перемкнутися на прийом.

Коли саме перемикати DE у 0? Наївне рішення «одразу після UDR = byte» — неправильне: байт ще лежить у зсувному регістрі й передається на лінію. Опустити DE до завершення = обрізати хвіст передачі.

Правильний патерн — використовувати переривання USART_TXC (Transmit Complete), яке спрацьовує після того, як останній біт вийшов на лінію (включно зі стоп-бітом):

#define DE_PIN PB0 // DE+RE̅ разом на одній нозі void rs485_tx_mode(void) { PORTB |= (1 << DE_PIN); } void rs485_rx_mode(void) { PORTB &= ~(1 << DE_PIN); } void rs485_send(const uint8_t *data, uint8_t len) { rs485_tx_mode(); // DE=1 — передаємо UCSRA |= (1 << TXC); // скинути TXC (він write-1-to-clear) for (uint8_t i = 0; i < len; i++) { while (!(UCSRA & (1 << UDRE))); // чекати порожнього буфера UDR = data[i]; } while (!(UCSRA & (1 << TXC))); // чекати ПОВНОГО завершення rs485_rx_mode(); // DE=0 — переходимо на прийом } // Альтернатива з TXC ISR — не блокує main: ISR(USART_TXC_vect) { rs485_rx_mode(); // автоматичний перехід на прийом } // Перед першою передачею дозволити: UCSRB |= (1 << TXCIE);
Прапор TXC vs UDRE. UDRE — «буфер порожній, можна записати наступний байт» (ще не передано). TXC — «передачу повністю завершено, шина вільна». Для RS-485 важливий саме TXC — переключатися на прийом лише після нього.
Термінуючі резистори. Схема Lab 8 показує 560 Ом між A та B на кінцях лінії — це термінатори, що гасять відбиття на довгих лініях. Значення ~120 Ом для витої пари — класичне; 560 Ом — компроміс для коротких лабораторних кабелів (кілька метрів). На довгих магістралях (100+ м) без правильних термінаторів — поява ghost-bits.

Мультипроцесорний режим UART (Lab 8, 9)

9-бітний режим — у кадрі 9 біт даних; 9-й біт служить маркером адресного байта (1) проти байта даних (0). Slave-пристрої ігнорують байти даних, допоки не отримають адресний байт зі своєю адресою — після чого приймають наступні байти даних.

Аналогово-цифровий перетворювач

Призначення та принцип

АЦП (ADC) перетворює аналоговий сигнал на цифровий (двійковий) код — даючи МК змогу працювати з давачами, контролювати напругу живлення тощо.

Перетворення складається з двох дій:

  1. Дискретизація за часом — вибірки у моменти t1, t2, ..., з частотою fs.
  2. Квантування за амплітудою — округлення миттєвого значення до найближчого рівня квантування.

Розрядність та роздільна здатність

Кількість рівнів = 2^N, де N — розрядність 8 біт → 256 рівнів (0 … 255) 10 біт → 1024 рівні (0 … 1023) — AVR ATmega32A 12 біт → 4096 рівнів 16 біт → 65536 рівнів Роздільна здатність за напругою (LSB): U_LSB = (U_ref) / 2^N Приклад: U_ref = 5 В, 10 біт → U_LSB = 5/1024 ≈ 4,88 мВ Зв'язок між виміряним кодом та напругою: U_вх = ADC_code · U_ref / 2^N

АЦП у AVR

Інтегрований модуль АЦП послідовних наближень. У ATmega32A: 10 біт, 8 каналів (ADC0–ADC7 на порту A), максимум 15 000 вибірок/с, інтегральна нелінійність 0,5 LSB, абсолютна похибка 2 LSB.

Вирівнювання результату (ADLAR) та порядок читання

Результат 10-бітного АЦП зберігається у двох регістрах ADCH:ADCL. Біт ADLAR (ADC Left Adjust Result) у регістрі ADMUX визначає, як саме 10 біт розподілені між цими двома байтами.

ADLAR = 0 (за замовчуванням) — вирівнювання вправо: ADCH: - - - - - - B9 B8 ADCL: B7 B6 B5 B4 B3 B2 B1 B0 Читати як: uint16_t result = ADC; // 0..1023 ADLAR = 1 — вирівнювання вліво: ADCH: B9 B8 B7 B6 B5 B4 B3 B2 ADCL: B1 B0 - - - - - - Якщо достатньо 8 біт точності — читати тільки ADCH: uint8_t result = ADCH; // 0..255
Правило читання (КРИТИЧНО): при ADLAR=0 завжди читайте ADCL перший, потім ADCH. Апаратура блокує ADC від оновлення регістрів між цими двома читаннями — інакше можна отримати «склеєне» значення з двох різних перетворень.
// ПРАВИЛЬНО: uint8_t lo = ADCL; // сперши молодший uint8_t hi = ADCH; // потім старший — ADC розблоковано uint16_t result = (hi << 8) | lo; // Або (компілятор згенерує правильно): uint16_t result = ADC; // avr-libc визначає ADC як 16-бітне читання // НЕПРАВИЛЬНО: uint8_t hi = ADCH; // ← блокує ADC uint8_t lo = ADCL; // ← читання, але високий байт вже старий! // ЯКЩО ADLAR=1 і достатньо 8 біт: uint8_t result = ADCH; // читати можна одразу, без ADCL

Диференціальні канали та вбудоване підсилення

Окрім 8 несиметричних каналів (ADC0–ADC7 відносно AGND), ATmega32A підтримує диференціальні канали — вимірювання різниці напруг між двома входами. Таких комбінацій 13, з яких 2 з можливістю вбудованого підсилювача.

  • Результат — знакове число у двійковому доповняльному коді

Опорна напруга: AVCC, AREF, внутрішні 2.56 В

Якість вимірювань АЦП безпосередньо залежить від стабільності опорної напруги. AVR дає три варіанти:

Схемні рекомендації:

  • AVCC з'єднати з VCC через LC-фільтр (10 мкГн + 100 нФ) або просто через фериту — зменшує цифровий шум від ядра
  • AGND з'єднати з GND у одній точці (зірка-заземлення) — уникає струмових петель
  • AREF завжди шунтувати керамічним конденсатором 0.1 мкФ на AGND, навіть коли використовується AVCC — бо AREF має прямий внутрішній зв'язок з АЦП

Типова помилка: встановити REFS1:0 = 11 (внутрішні 2.56 В), але зовні залишити підключення AVCC до AREF напряму — через AREF «коротится» внутрішня 2.56 В з 5 В, що виведе аналоговий модуль з ладу. Завжди перевіряйте схему перед вибором опорної.

SPI та I²C (TWI)

SPI — Serial Peripheral Interface

SPI — високошвидкісний повнодуплексний синхронний 3-провідний (+1 Slave Select) протокол. Розроблений Motorola, став де-факто стандартом.

Шина master–slave: master ініціює обмін і подає тактовий сигнал. AVR може працювати і як master, і як slave; периферія (АЦП, ЦАП, пам'ять, дисплеї) — як правило, тільки slave.

ЛІНІЯНАПРЯМОКОПИС

MOSI (Master Out Slave In)Master → SlaveДані від master
MISO (Master In Slave Out)Master ← SlaveДані від slave
S̅S̅ (Slave Select)Master → SlaveАктивний «0» — вибраний slave

Принцип роботи SPI

Основа модуля — 8-розрядний зсувний регістр. MOSI master'а з'єднаний з SI slave'а, MISO — з SO. Разом вони утворюють 16-розрядний кільцевий зсув: за 8 тактів SCK 8 біт пересуваються від master до slave, і одночасно 8 біт — у зворотному напрямку.

Підключення кількох slave'ів:

  • Одинарне: 1 master, 1 slave; 3 або 4 провідники.
  • Зірка (multi-slave): MISO/MOSI/SCK спільні, у кожного slave своя окрема S̅S̅-лінія від master.
CPOL та CPHA (режими 0–3). Четыре комбінації полярності/фази тактового сигналу визначають, коли slave вибирає біт (наростаючий чи спадаючий фронт). Режими 0 та 3 — найпоширеніші. Обидва пристрої мають бути налаштовані на один режим.

  • CPOL (Clock Polarity) — рівень SCK у простої (idle): 0 = низький, 1 = високий
  • CPHA (Clock Phase) — коли семплюються дані: 0 = перший фронт (leading edge), 1 = другий фронт (trailing edge)

I²C (також Two-Wire Interface, TWI) — двопровідний синхронний протокол від Philips (1982). Дозволяє до 127 пристроїв на одній парі ліній.

Керуючі сигнали I²C

Передача на I²C складається з таких елементів:

  • START — перехід SDA з 1 у 0 при SCL=1 (master захоплює шину)
  • STOP — перехід SDA з 0 у 1 при SCL=1 (master звільняє шину)
  • Байт даних — 8 біт SDA, синхронізовані SCL, старший біт першим
  • ACK / NACK — 9-й такт: приймач опускає SDA у 0 (ACK) або залишає 1 (NACK)
  • Repeated START — повторний START без попереднього STOP (для зміни напрямку без звільнення шини)

// Приклад: записати один байт у регістр slave (адреса 0x50, регістр 0x10, байт 0xAB) void i2c_start(void) { TWCR = (1 << TWINT) | (1 << TWSTA) | (1 << TWEN); while (!(TWCR & (1 << TWINT))); // очікуємо (TWSR & 0xF8) == 0x08 } void i2c_write(uint8_t data) { TWDR = data; TWCR = (1 << TWINT) | (1 << TWEN); while (!(TWCR & (1 << TWINT))); // очікуємо 0x18 (для SLA+W), 0x28 (для даних) або 0x40 (для SLA+R) } void i2c_stop(void) { TWCR = (1 << TWINT) | (1 << TWSTO) | (1 << TWEN); } void write_byte(uint8_t slave_addr, uint8_t reg, uint8_t val) { i2c_start(); // 0x08 i2c_write((slave_addr << 1) | 0); // SLA+W; очікуємо 0x18 i2c_write(reg); // 0x28 i2c_write(val); // 0x28 i2c_stop(); }
Чому TWSR замасковано 0xF8? Молодші 3 біти TWSR — це TWPS0/TWPS1 (дільник швидкості) і зарезервований біт. Маскування вибирає лише старші 5 біт зі значенням коду стану. Без маски ви отримаєте некоректні числа.

10-бітна адресація I²C

Стандарт I²C також підтримує 10-бітні адреси для кращого маштабування великих систем. Сумісна з 7-бітними пристроями на тій самій шині.

Паразитне живлення (parasite power). Пристрій живиться безпосередньо з лінії DQ через вбудований конденсатор — VCC не підключений (або на GND). Працює, але під час CONVERT T лінію треба утримувати у «1» (або перемкнути ногу МК на сильну підтяжку), бо давач споживає струм для перетворення. Зовнішнє живлення через VCC простіше і стабільніше.
CRC у 1-Wire. 64-бітний ROM-ID і вміст scratchpad захищені CRC-8/MAXIM (poly=0x31, refin=refout=true, xorout=0). Саме цей CRC згадується в Lab 8 варіант 11. DS18B20 обчислює його апаратно — ви можете перевірити коректність на стороні МК.

UART, RS-232, RS-485
UART
Universal Asynchronous Receiver/Transmitter
Асинхронний послідовний інтерфейс без окремої лінії синхронізації.
USART
Universal Synchronous/Asynchronous Receiver/Transmitter

Transmit Data / Receive Data
Лінії передачі та прийому даних UART.
XCK
External Clock
Синхросигнал USART у синхронному режимі.
Baud
Baud rate
Кількість символів (біт) за секунду у послідовному каналі.

USART Baud Rate Register
Регістр дільника для формування бодрейту.
UDR
USART Data Register
Буферний регістр даних (TX і RX мають спільну адресу, але різні регістри).
UCSRA / UCSRB / UCSRC
USART Control & Status Register A/B/C
Регістри керування USART: дозволи, прапорці, формат кадру.
UDRE
USART Data Register Empty
Прапор: буфер TX порожній, можна писати наступний байт.

Receive Complete / Transmit Complete
Прапорці: байт прийнятий / передачу повністю завершено.

U2X
Double USART speed
Біт подвоєння швидкості (дільник /8 замість /16).
MPCM
Multi-Processor Communication Mode
Режим для мережі МК: slave ігнорує дані, доки не отримає адресу.

Transmit/Receive Bit 8

RS-232
Recommended Standard 232
Класичний стандарт ПК-послідовний порт, ±3…±15 В, DB9.
RS-485
Recommended Standard 485 (EIA/TIA-485)
Диференціальний інтерфейс для промислових мереж до 1200 м.
TTL
Transistor-Transistor Logic
Логічні рівні 0 / +5 В — як у UART виводах МК.
DTE / DCE
Data Terminal Equipment / Data Communication Equipment

RTS / CTS
Request To Send / Clear To Send
Лінії апаратного керування потоком у RS-232.
DTR / DSR
Data Terminal Ready / Data Set Ready
Сигнали готовності терміналу/модему.
DCD / RI
Data Carrier Detect / Ring Indicator
Модемні сигнали: наявність несучої / вхідний виклик.
XON / XOFF
ASCII 0x11 / 0x13
Програмне керування потоком у RS-232 (start/stop transmit).
DE / RE̅
Driver Enable / Receiver Enable (MAX485)
Дозвіл передавача / приймача трансивера RS-485.
RO / DI
Receiver Output / Driver Input (MAX485)
Цифрові виводи MAX485: вихід прийнятих даних / вхід для передачі.
CRC
Cyclic Redundancy Check
Контрольна сума з поліноміальним діленням для виявлення помилок передачі.
FIFO
First In, First Out
Кільцевий буфер для розв'язки ISR від основного коду.
COMPIM
COM Port Physical Interface Model (Proteus)
Компонент Proteus для підключення симуляції до фізичного/віртуального COM-порту ПК.
VSPD
Virtual Serial Port Driver
Утиліта для створення пари з'єднаних віртуальних COM-портів у Windows.
ModBus
Modicon Bus (industry protocol)
Промисловий протокол обміну поверх RS-485; використовує CRC-16/MODBUS.
SPI, I²C, 1-Wire
SPI
Serial Peripheral Interface
Синхронний повнодуплексний 4-провідний інтерфейс від Motorola.
SCK / SCLK
Serial Clock
Тактова лінія SPI, формується master'ом.
MOSI / MISO
Master Out Slave In / Master In Slave Out
Дві лінії даних SPI, один напрямок кожна.
SS̅ / CS̅
Slave Select / Chip Select
Лінія вибору slave'а в SPI, активна «0».
SI / SO
Slave Input / Slave Output
Альтернативні назви MOSI/MISO з боку slave-пристрою.
SPCR / SPSR / SPDR
SPI Control / Status / Data Register
Регістри модуля SPI у AVR.
CPOL / CPHA
Clock Polarity / Clock Phase
Два параметри синхронізації SPI, що визначають 4 режими 0–3.
SPIF / WCOL
SPI Interrupt Flag / Write COLlision
Прапорець завершення передачі / помилка запису під час активного обміну.
I²C / IIC
Inter-Integrated Circuit
Двопровідний синхронний протокол від Philips (1982).
TWI
Two-Wire Interface
Atmel-назва для I²C, щоб уникнути ліцензійних питань.
SDA / SCL
Serial Data / Serial Clock
Двонапрямлена лінія даних / тактова лінія I²C.
TWBR / TWCR / TWSR / TWDR / TWAR
TWI Bit Rate / Control / Status / Data / Address Register
Регістри модуля TWI AVR.
TWINT / TWEN / TWSTA / TWSTO / TWEA
TWI: Interrupt / Enable / Start / Stop / Enable ACK
Біти керування TWCR.
ACK / NACK
Acknowledge / Not Acknowledge
9-й такт I²C: приймач підтверджує (SDA=0) або відмовляє (SDA=1).
SLA
SLave Address
7- або 10-бітна адреса slave-пристрою.
R/W
Read / Write bit
8-й біт адресного байта I²C: 0 = запис, 1 = читання.
Sr / RESTART
Repeated START condition
Повторний START без попереднього STOP — зміна напрямку без звільнення шини.
1-Wire
Dallas 1-Wire bus
Однопровідний протокол від Maxim/Dallas; DS18B20, DS1822, iButton.
DQ
Data Q(line) — 1-Wire data pin
Єдина сигнальна лінія 1-Wire.
ROM ID
Read-Only Memory Identifier (64-bit)
Унікальний 64-бітний адрес 1-Wire пристрою, лазерно запрограмований.

ADC Control and Status Register A

ADCH / ADCL
ADC result High / Low byte
Старший/молодший байти 10-бітного результату. Читати ADCL першим!

ADC Enable / Start Conversion / Interrupt Enable / Flag / Auto Trigger Enable
Біти керування у ADCSRA.
ADLAR
ADC Left Adjust Result
Біт у ADMUX: 0 = right-adjusted, 1 = left-adjusted.

ADC PreScaler
Біти прескалера тактової частоти АЦП (2…128).

Reference Voltage
