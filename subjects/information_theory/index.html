РОЗДІЛ 01

Поняття інформації

⬡ Інформація, дані, повідомлення

Будь-який прояв матеріального світу, зафіксований живою істотою або приладом, несе інформацію. Формалізовані набори символів називаються даними. Дані, отримані від джерела, стають повідомленнями. Інформацією стають лише ті повідомлення, що знімають невизначеність — тому теорія інформації вимірює інформативність кількісно, без урахування смислу.

⬡ Алфавіт повідомлення

Представлення інформації потребує набору символів — алфавіту. Алфавіт може бути множиною числових значень фізичної величини, цифр десяткової системи, букв української мови тощо. Для абстрагування від смислу кількісну міру вводять без урахування цінності повідомлення для одержувача.

⬡ Сигнал як носій повідомлення

Сигнал — фізичний процес, що переносить інформацію. Розрізняють сигнали:

  • Зорові — телевізійне зображення, друкований текст
  • Звукові — мова, музика, дзвоник
  • Електричні — імпульси, напруга, струм
  • Радіосигнали — електромагнітні хвилі

Один тип сигналу може викликати інший — електричний у дзвонику породжує звуковий, світловий у фотоелементі породжує електричний.

⬡ Параметри сигналу
  • Tc — тривалість сигналу
  • Fc — ширина частотного спектра
  • Pc — середня потужність

Для надійної передачі ці параметри розглядають у взаємозв'язку — вони можуть доповнювати один одного.

⬡ Біт та народження теорії інформації

У 1946 році американський статистик Джон Тьюкі запропонував термін БІТ (BIT — від BInary digiT) для позначення двійкового розряду. У 1948 Клод Шеннон у роботі «A Mathematical Theory of Communication» використав біт як одиницю виміру інформації, а мірою кількості — функцію, названу ним ентропією.

Шеннон зауважив, що різні букви несуть різну кількість інформації: часті — менше, рідкісні — більше. Зв'язок між частотою (ймовірністю) появи та кількістю інформації виражається ентропією.
РОЗДІЛ 02

Кількісна оцінка інформації

⬡ Підхід Хартлі (1928): рівноймовірні події

Якщо повідомлення складається з n знаків, кожен з яких приймає m станів, то загальна кількість можливих повідомлень:

N = m n
кількість можливих повідомлень

За припущення рівноймовірності, кількість інформації за Хартлі:

I = n · log m = log m n = log N
формула Хартлі
⬡ Підхід Шеннона (1948): нерівноймовірні події

Коли символи мають різні ймовірності появи, кількість інформації обчислюється за формулою Шеннона:

H r ( X ) = − ∑ i = 1 K p ( x i ) · log r p ( x i )
(1.1) формула Шеннона
де: p ( x i ) — ймовірність символу x i ; K — розмір алфавіту; r — основа логарифма (визначає одиниці).
⬡ Канонічний приклад: комірка пам'яті

Якщо ймовірність запису 0 або 1 однакова ( p = 1 / 2 ):

H 2 ( 2 ) = 1 2 log 2 2 + 1 2 log 2 2 = 1
ентропія двійкової комірки = 1 біт
⬡ Одиниці вимірювання інформації

Основа логарифма у формулі Шеннона визначає одиницю виміру:

Основа Одиниця Походження
2 біт (binary digit) двійкова система — стандарт
e нат (natural unit) натуральний логарифм
10 хартлі / діт (decit) десяткова система

Перерахунок: 1 нат = log 2 e ≈ 1.443 біт; 1 хартлі ≈ 3.322 біт.

⬡ Максимальна ентропія: формула Хартлі

Ентропія максимальна, коли всі повідомлення мають однакову ймовірність. Підставляючи p i = 1 / k у формулу Шеннона:

H max ( X ) = − ∑ i = 1 k 1 k · log 2 1 k = log 2 k
(1.2) формула Хартлі
⬡ Канонічний приклад: дискретна випадкова величина

Знайти ентропію X за розподілом:

xi x₁ x₂ x₃ x₄ x₅ x₆
pi 0.4 0.3 0.15 0.1 0.03 0.02
H ( X ) = 0.4 · 1.322 + 0.3 · 1.737 + 0.15 · 2.737 + 0.1 · 3.22 + 0.03 · 5.059 + 0.02 · 5.644 = 2.0573 біт/повідомлення
приклад розрахунку ентропії
⬡ Приклад: 8-бітне зображення 600×800

Зображення містить 480000 пікселів, кожен приймає 2 8 = 256 станів з рівною ймовірністю:

I = n · log 2 m = 480000 · log 2 256 = 480000 · 8 = 3.84 · 10 6 біт
кількість інформації за Хартлі
⬡ Приклад: чорні та білі кульки

В урні 1000 кульок: 100 чорних ( p чорн = 0.1 ) і 900 білих ( p біл = 0.9 ). Кількість інформації за один розіграш (за Шенноном):

I = − ( 0.1 · log 2 0.1 + 0.9 · log 2 0.9 ) = 0.47 дв.од.
ентропія двох нерівноймовірних подій

Менше за log 2 2 = 1 біт — підтверджує, що при нерівноймовірності інформативність нижча за максимум.

Властивості ентропії: (1) H = 0 якщо одна подія достовірна; (2) H ≥ 0 , дійсна та обмежена; (3) для двох альтернатив: 0 ≤ H ≤ 1 ; (4) адитивність для незалежних джерел; (5) H max = log 2 k при рівноймовірності.
РОЗДІЛ 03

Ентропія та її види

⬡ Безумовна ентропія

Найбільш вживана — слово «безумовна» здебільшого опускають. Це кількість інформації на один елемент повідомлення за умови незалежності елементів:

H = I n = n · log m n = log m
(7.1) безумовна ентропія
⬡ Ентропії джерела та приймача

Множина вихідних елементів a k утворює ансамбль повідомлень джерела A. Аналогічно, для приймача B:

H ( A ) = − ∑ k p ( a k ) · log 2 p ( a k )
(7.2) ентропія джерела
H ( B ) = − ∑ l p ( b l ) · log 2 p ( b l )
(7.3) ентропія приймача

У ідеальному каналі без втрат H ( A ) = H ( B ) .

⬡ Умовні ймовірності

Якщо при n переданих повідомленнях символ A з'явився m разів, B — n разів, а спільно AB — k разів:

p ( A ) = m n , p ( B ) = n n , p ( A B ) = k n
(7.4-7.5) безумовні та сумісні ймовірності
p ( A B ) = p ( B ) · p ( A / B ) = p ( A ) · p ( B / A )
(7.6) теорема множення ймовірностей
⬡ Часткова умовна ентропія

Невизначеність на стороні приймача за умови, що джерелом надіслано конкретний a k :

H ( b l / a k ) = − ∑ l p ( b l / a k ) · log 2 p ( b l / a k )
(7.7) часткова умовна (приймача)
H ( a k / b l ) = − ∑ k p ( a k / b l ) · log 2 p ( a k / b l )
(7.8) часткова умовна (джерела)
⬡ Загальна умовна ентропія

Усереднена невизначеність по всіх можливих сигналах джерела — кількість інформації, що залишається невизначеною після прийняття:

H ( B / A ) = − ∑ k p ( a k ) ∑ l p ( b l / a k ) · log 2 p ( b l / a k )
(7.9) загальна умовна ентропія
⬡ Властивість незалежності

Якщо джерело і приймач статистично незалежні, умовні ентропії дорівнюють безумовним:

H ( A / B ) = H ( A ) ; H ( B / A ) = H ( B )
(7.10) незалежність
⬡ Ентропія об'єднання

Невизначеність того, що буде послано A та прийнято B :

H ( A , B ) = − ∑ k ∑ l p ( a k , b l ) · log 2 p ( a k , b l )
(7.11) ентропія об'єднання
H ( A , B ) = H ( A ) + H ( B / A ) = H ( B ) + H ( A / B )
(7.12) зв'язок об'єднання з умовною
⬡ Канонічний приклад: умовна ентропія для пари К/Т

При передачі 100 повідомлень довжиною 5 символів (всього 500 символів) символ К з'явився 50 разів, Т — 30 разів, а пара КТ — 10 разів. Знайти H ( K / T ) та H ( T / K ) .

p ( K ) = 50 500 = 0.1 ; p ( T ) = 30 500 = 0.06 ; p ( K T ) = 10 500 = 0.02
безумовні та сумісна ймовірності
p ( K / T ) = p ( K T ) p ( T ) = 0.02 0.06 = 0.33 p ( T / K ) = p ( K T ) p ( K ) = 0.02 0.1 = 0.2
умовні ймовірності
H ( K / T ) = − ( 0.33 · log 2 0.33 + 0.67 · log 2 0.67 ) = 0.9149 біт/символ H ( T / K ) = − ( 0.2 · log 2 0.2 + 0.8 · log 2 0.8 ) = 0.7219 біт/символ
часткові умовні ентропії
Умовна ентропія завжди менша або дорівнює безумовній: H ( A / B ) ≤ H ( A ) . Знання про B не може збільшити невизначеність про A — воно або зменшує її, або не змінює.
РОЗДІЛ 04

Надлишковість повідомлень

⬡ Поняття надлишковості

Надлишковість показує відносну «недовантаженість» інформацією символів алфавіту. Вона безрозмірна та залежить лише від статистики:

D = 1 − H H max
(8.1) загальна надлишковість
де: μ = H / H max — коефіцієнт стиску (відносна ентропія).
⬡ Корекційна надлишковість

Не вся надлишковість шкідлива! Для підвищення завадостійкості її вводять штучно — у вигляді контрольних розрядів:

n к = n − n и
(8.5) абсолютна корекційна надлишковість
⬡ Види надлишковості

Розрізняють два джерела надлишковості:

D p = 1 + ∑ k p k · log p k log m
(8.2) надлишковість через нерівноймовірність
D = D u + D p − D u · D p
(8.4) повна інформаційна надлишковість
де: D u — надлишковість через статистичні зв'язки між символами; m — потужність алфавіту.
⬡ Канонічний приклад: алфавіт {a, b, c, d}

Дано: p a = 0.2 , p b = 0.3 , p c = 0.4 , p d = 0.1 .

H max = log 2 4 = 2 біт/символ H = 0.4644 + 0.5211 + 0.5288 + 0.3322 = 1.8465 біт/символ D = 1 − 1.8465 2 = 0.0768
приклад розрахунку надлишковості

Лише ~7.7% «зайвих» бітів — алфавіт майже повністю використаний.

⬡ Корекційна (штучна) надлишковість

На відміну від природної, корекційна надлишковість вводиться навмисно — у вигляді контрольних розрядів. Вона збільшує довжину коду, але дозволяє виявляти або виправляти помилки:

D к = n − n и n и
(8.6) відносна корекційна надлишковість
Природна надлишковість мов: ~50% для української, 50–70% для англійської. Це дозволяє розуміти текст з помилками й опечатками — і дає простір для стискання (Шеннон, 1951).
РОЗДІЛ 05

Дискретизація та квантування

⬡ Перехід неперервний → дискретний

При передачі неперервних сигналів виникають апаратурні похибки і нестабільність каналу зв'язку. Перетворення неперервного сигналу в дискретний усуває ці проблеми, але вводить власні похибки. Існує три способи:

  • Дискретизація — квантування за часом
  • Квантування — за рівнем
  • Квантизація — комбіноване (за часом і рівнем)
⬡ Теорема Котельникова

Якщо неперервна функція s ( t ) має обмежений спектр (без частот вище F m ), вона повністю визначається своїми відліками через інтервал Δ t = 1 / ( 2 F m ) :

s ( t ) = ∑ k = − ∞ ∞ s ( k Δ t ) · sin ( ω m ( t − k Δ t ) ) ω m ( t − k Δ t )
(2.1) ряд Котельникова
⬡ Шум квантування за рівнем

При квантуванні з кроком Δ s вноситься похибка, яку усунути неможливо:

σ кв 2 = Δ s 2 12
(2.2) середньоквадратичний шум квантування
⬡ Відстань Кульбака-Лейблера (відносна ентропія)

Спосіб порівняти два розподіли ймовірностей p та q :

D ( p ‖ q ) = ∑ x p ( x ) · log p ( x ) q ( x )
(2.3) відстань Кульбака-Лейблера
⬡ Крок квантування за заданою похибкою

Задаємо допустиму відносну похибку δ y у відсотках:

h = 2 · x max · δ y 100
(3.1) крок квантування
N = x max h + 1
кількість рівнів (при xmin = 0)
⬡ Канонічний приклад: квантування з заданою точністю

Неперервна функція з x max = 173 квантується з похибкою δ y = 0.25 % :

h = 2 · 173 · 0.25 100 = 0.865 N = 173 0.865 = 200 рівнів Розрядність: ⌈ log 2 200 ⌉ = 8 розрядів
приклад з конспекту, стор.10
⬡ Ресемплінг зображень

Ресемплінг (resampling) — зміна кроку дискретизації, тобто розмірів зображення. Алгоритми:

  • Найближчий сусід (nearest neighbor) — дублювання/викидання пікселів. Швидко, але різко
  • Білінійна інтерполяція (bilinear) — зважена сума 4 сусідніх пікселів
  • Бікубічна інтерполяція (bicubic) — складніший алгоритм з 16 пікселями

Збільшення зображень майже завжди погіршує різкість через розмиття.

⬡ Хибні контури

При малій кількості рівнів квантування L на пологих ділянках зображення з'являються хибні контури — стрибкоподібні переходи яскравості, яких немає в оригіналі. Ефект особливо помітний на градієнтах та плавних переходах.

Практичне завдання: для grayscale-зображення з понад 64 градаціями виконати дискретизацію з кроками 2 та 4, квантування на 8/16/64 рівні. Для кожного варіанту обчислюють ентропію та відносну ентропію Кульбака-Лейблера, а відновлення виконують методом найближчого сусіда.
РОЗДІЛ 06

Канал зв'язку та пропускна здатність

⬡ Об'єм сигналу та каналу

Сигнал та канал характеризуються трьома параметрами: тривалість, ширина смуги, рівень. Об'єм — їх добуток:

V c = T c · F c · H c ; V k = T k · F k · H k
об'єми сигналу та каналу

Умова передачі: V k ≥ V c .

⬡ Формула Шеннона-Хартлі

Пропускна здатність неперервного каналу з шумом:

C = F · log 2 ( 1 + P c P з )
(4.8) формула Шеннона-Хартлі
де: F — ширина смуги частот; P c / P з — відношення сигнал/шум (SNR).
⬡ Швидкість і пропускна здатність

Швидкість передачі — кількість інформації за одиницю часу:

V = I T або V = n · H T
(4.1, 4.2) швидкість передачі [дв.од./с]

Швидкість обмежена властивостями каналу. Максимальна досяжна швидкість — пропускна здатність C :

C = lim T → ∞ log M T
(4.3) пропускна здатність дискретного каналу
⬡ Двійковий канал без завад

Якщо тривалість одного двійкового символу τ :

C = 1 τ
(4.5) пропускна здатність двійкового каналу

Це фундаментальна межа: не можна передавати швидше, ніж ставити нові символи в канал.

⬡ Канонічний приклад: пропускна здатність каналу з шумом

Канал має смугу Δ F = 70 кГц, потужність сигналу P c = 30 мкВт, шуму P з = 1.15 · 10 − 2 мкВт:

C = 70 · 10 3 · log 2 ( 1 + 30 · 10 − 6 1.15 · 10 − 8 ) = 0.626 · 10 6 дв.од./с
приклад з конспекту, стор.14
⬡ Рівні в Неперах та децибелах

Логарифмічні одиниці для співвідношень потужностей:

H c = 1 2 · ln P c P з [ Нп ] H c = 10 · lg P c P з [ дБ ]

Перерахунок: 1 Нп = 8.69 дБ; 1 Нп відповідає відношенню потужностей e 2 ≈ 7.388 .

РОЗДІЛ 08

Модульовані сигнали

⬡ Що таке модуляція

Модуляція — процес вбудовування інформаційного (низькочастотного) сигналу в сигнал-носій (високочастотний). Низькочастотні сигнали погано випромінюються та поглинаються в середовищі — модуляція переносить їх спектр у діапазон, де поширення ефективне.

⬡ Амплітудна модуляція

При тональній (гармонічній) модуляції огинаюча несучого коливання змінюється за законом керуючого сигналу:

a ( t ) = A 0 [ 1 + M · sin ( Ω t − γ ) ] · sin ( ω 0 t + Θ 0 )
(6.2) АМ-коливання
де: M = Δ A m / A 0 — коефіцієнт глибини модуляції; ω 0 — несуча частота; Ω — частота модулюючого сигналу.
⬡ Високочастотний носій

Базовий несучий сигнал — гармонічне коливання:

c ( t ) = A · sin ( ω 0 t + Θ ) = A · sin Ψ
(6.1) несучий сигнал
де: A — амплітуда, Θ — початкова фаза, Ψ — повна фаза в момент t .

Якщо A = const та Θ = const — це чисте гармонічне коливання. Якщо A чи Ψ змінюються — коливання модульоване.

⬡ Спектр АМ-коливання

Тригонометричне розкриття добутку дає три спектральні складові:

a ( t ) = A 0 · sin ( ω 0 t + Θ 0 ) − M · A 0 2 · cos [ ( ω 0 + Ω ) t + Θ 0 + γ ] + M · A 0 2 · cos [ ( ω 0 − Ω ) t + Θ 0 − γ ]
(6.3) спектральне розкладання АМ
Амплітуда ↑ │ M·A₀/2 A₀ M·A₀/2 │ │ │ │ │ │ │ │ │ ● ● ● │ │ │ │ └──────────┼──────────┼──────────┼──────→ частота ω₀ − Ω ω₀ ω₀ + Ω ←──── ширина спектру = 2Ω ────→
⬡ Потужності АМ-сигналу

В коливному контурі з опором r :

Режим Потужність
несучої хвилі (без модуляції) P 0 = A 0 2 · r / 2
максимальний P max = P 0 ( 1 + M ) 2
мінімальний P min = P 0 ( 1 − M ) 2
середня за період модуляції P avg = P 0 ( 1 + 0.5 M 2 )

При M = 1 (стопроцентна модуляція) P max = 4 P 0 , P min = 0 .

При АМ-модуляції виникають дві бокові частоти: ω 0 + Ω (верхня) та ω 0 − Ω (нижня). Ширина спектру АМ-сигналу = 2 Ω .
РОЗДІЛ 09

Оптимальне кодування

⬡ Префіксні коди та умова Фано

Префіксний код — такий, у якому жодне кодове слово не є початком (префіксом) іншого. Це гарантує однозначне декодування потоку без розділювачів. Префіксні коди представляються кодовим деревом: символи — листя, шлях від кореня — кодова послідовність.

⬡ Нерівність Крафта

Необхідна та достатня умова існування префіксного коду з довжинами L 1 , L 2 , … , L n :

∑ i = 1 n 2 − L i ≤ 1
нерівність Крафта
⬡ Теорема кодування джерела (Шеннон)

Для будь-якого префіксного коду середня довжина L ― задовольняє:

H ( X ) ≤ L ― < H ( X ) + 1
теорема Шеннона про кодування джерела

Нижня межа L m = H ( X ) — теоретично недосяжна, але можна підійти як завгодно близько за допомогою блокового кодування.

⬡ Алгоритм Шеннона-Фано

Покрокова процедура розбиття згори вниз:

  1. Сортувати символи за спаданням ймовірностей
  2. Розбити впорядкований список на дві групи з якомога ближчими сумами
  3. Першій групі присвоїти 0, другій — 1 (черговий правий розряд коду)
  4. Рекурсивно повторити для кожної групи з ≥2 символами
⬡ Канонічний приклад Шеннона-Фано

Множина P = { 0.4 , 0.2 , 0.15 , 0.15 , 0.1 } дає коди:

x₁ 0.4 00 0
x₂ 0.2 10 100
x₃ 0.15 110 101
x₄ 0.15 111 110
x₅ 0.1 01 111

середня довжина за Фано
⬡ Алгоритм Хаффмана (1952)

Процедура злиття знизу вгору — гарантовано оптимальна:

  1. Розташувати символи за спаданням ймовірностей
  2. Об'єднати два символи з найменшими ймовірностями в один з ймовірністю-сумою
  3. Впорядкувати список повторно
  4. Повторити, поки не залишиться один елемент (корінь дерева)
  5. Гілкам присвоїти 0/1, прочитати коди від кореня до листя
⬡ Канонічний приклад Хаффмана

Та сама множина — алгоритм будує дерево знизу вгору, об'єднуючи на кожному кроці два найменші:

Алгоритм Хаффмана (знизу вгору): Крок 1: {0.4, 0.2, 0.15, 0.15, 0.1} об'єднуємо найменші: 0.15 + 0.1 = 0.25 Крок 2: {0.4, 0.2, 0.15, 0.25} об'єднуємо: 0.2 + 0.15 = 0.35 Крок 3: {0.4, 0.25, 0.35} об'єднуємо: 0.25 + 0.35 = 0.6 Крок 4: {0.4, 0.6} фінал: 0.4 → 0, 0.6 → 1 У групі 0.6: 0.35→0, 0.25→1 У групі 0.35: 0.2→0, 0.15→1 У групі 0.25: 0.15→0, 0.1→1

L = 1 · 0.4 + 2 ( 0.2 + 0.15 + 0.15 + 0.1 ) = 1.6

⬡ Арифметичне кодування

Запропоноване Еліасом у 1960-х. Ключова ідея — повідомлення представляється одним двійковим дробом з інтервалу [ 0 , 1 ) . На відміну від Хаффмана, він досягає теоретичної межі ентропії точніше — особливо коли ймовірності символів сильно нерівноймовірні.

⬡ Стиск без втрат: RLE

Run-Length Encoding — найпростіший підхід. Послідовності повторюваних байтів замінюються парою (лічильник, значення). Ефективний для зображень з великими однотонними областями, неефективний для тексту з малою кількістю послідовних повторень.

⬡ Родина Лемпела-Зіва

Серія алгоритмів, що використовують уже опрацьовану частину повідомлення як «довідник»:

Алгоритм Рік Структура Особливість
LZ77 1977 Біжуче вікно Трійки (offset, length, next)
LZSS 1982 Біжуче вікно 1-бітний префікс розрізнення
LZ78 1978 Динамічний словник Пари (індекс, символ)
LZW 1984 Розширений словник Ініціалізація 256 символами
Сучасні стандарти стиску використовують комбінації: DEFLATE (ZIP, gzip, PNG) = LZ77 + Хаффман; GIF = LZW; bzip2 = BWT + Хаффман; JPEG = DCT + квантування + Хаффман (з втратами).

⬡ Застосування на текстах і зображеннях

Алгоритми оптимального кодування знаходять застосування у двох основних класах джерел:

  • Текст — кожен символ розглядається як окреме повідомлення; ймовірності визначаються частотним аналізом. Для української мови коефіцієнт стиску μ ~ 0.5, тобто половина об'єму повідомлення є надлишковою.
  • Зображення — кожен піксель (або значення яскравості) розглядається як повідомлення. У монохромних з 256 рівнями яскравості розподіл часто далекий від рівноймовірного, що дозволяє ефективно стискати методом Хаффмана.

Для досягнення заданої точності апроксимації L − L m ≤ ε застосовується блокове кодування — об'єднання сусідніх символів у пари, трійки тощо.

РОЗДІЛ 10

Завадостійкі коди

⬡ Чому потрібні завадостійкі коди

На сигнал у каналі діють шуми, які спотворюють біти. Часто потрібно ймовірність помилки 10 − 6 , інколи навіть 10 − 9 . Звичайний n-розрядний код не захищений: усі 2 n комбінацій дозволені, тому будь-яка помилка дає іншу «дозволену».

Завадостійкий (коректуючий) код — використовує лише частину можливих комбінацій. Заборонені комбінації — індикатори помилок.

⬡ Кодова відстань Хемінга

Кодова відстань d між двома кодовими словами — кількість позицій, у яких вони відрізняються (= XOR + підрахунок одиниць). Мінімальна кодова відстань d min коду — найменше d серед усіх пар дозволених комбінацій. Вона визначає коректуючі властивості коду.

⬡ Умови коректуючої здатності
d min ≥ t + 1
(9.1) виявлення t помилок
d min ≥ t + s + 1
(9.2) виявлення t + виправлення s
d min ≥ 2 s + 1
(9.3) виправлення s помилок
⬡ Параметри коду Хемінга

Загальна довжина n = n 0 + r , де n 0 — інформаційні, r — надлишкові розряди. Для виявлення будь-якого спотвореного розряду:

2 r − 1 ≥ n = n 0 + r

⬡ Декодування з виправленням помилки

Припустимо, помилка у 5-му розряді (α₅: 0→1). Прийнято 1010111111. Перевірки:

b 1 = 1 ⊕ 1 ⊕ 1 ⊕ 0 ⊕ 0 = 1 b 2 = 1 ⊕ 1 ⊕ 1 ⊕ 0 ⊕ 1 = 0 b 3 = 1 ⊕ 1 ⊕ 1 ⊕ 0 = 1 b 4 = 1 ⊕ 0 ⊕ 1 = 0
синдром b₄b₃b₂b₁ = 0101₂ = 5

(11.1) поліноміальне представлення
⬡ Систематичне кодування циклічного коду

Кодове слово F ( x ) = U ( x ) · x r + R ( x ) , де R ( x ) — остача від ділення U ( x ) · x r на твірний поліном K ( x ) . Виявлення помилки — за ненульовою остачею від ділення прийнятого F * ( x ) на K ( x ) .

⬡ Коди Ріда-Соломона

Узагальнення циклічних кодів на символи з поля GF ( 2 m ) . Параметри:

  • n = 2 m − 1 — довжина у символах
  • k — інформаційні символи
  • d = n − k + 1 — мінімальна відстань (MDS-код)
  • t = ⌊ n − k 2 ⌋ — кількість виправних символьних помилок
⬡ Ключове рівняння декодування РС

Алгоритм декодування зводиться до розв'язання:

Λ ( z ) · S ( z ) ≡ Ω ( z ) ( mod z 2 t )
ключове рівняння Ріда-Соломона
де: Λ ( z ) — поліном локаторів помилок, S ( z ) — поліном синдромів, Ω ( z ) — поліном значень помилок. Розв'язується алгоритмами Берлекемпа-Мессі або Евкліда.
Коди Ріда-Соломона захищають від пакетів помилок (burst errors). Тому застосовуються в CD/DVD/Blu-ray (CIRC), QR-кодах, цифровому телебаченні (DVB), супутниковому зв'язку, RAID-6, місіях NASA (Voyager, Mars rovers).
⬡ Канонічний приклад: побудова циклічного коду

Інформаційний поліном U ( x ) = x 3 + x 2 + 1 ↔ 1101; твірний K ( x ) = x 3 + x + 1 ↔ 1011.

U ( x ) · x 3 = x 6 + x 5 + x 3 ↔ 1101000
множення на xr
Ділення 1101000 на 1011 (двійкове, XOR): 1101000 ÷ 1011 = частка 1110, остача 001 F(x) = U(x)·x³ ⊕ R(x) = 1101000 ⊕ 001 = 1101001 ┌────────┬───────┐ │ 1101 │ 001 │ ← кодове слово └────────┴───────┘ інформ. контр.

Перевірка: 1101001 ділиться на 1011 без остачі — ознака правильної кодової комбінації.

⬡ Метод гіпотез для виявлення помилки

Якщо прийнято F * ( x ) з помилкою (наприклад, 1101011):

  1. Поділити на K ( x ) → остача x 2 ≠ 0 (є помилка)
  2. Послідовно інвертувати кожен розряд F *
  3. Ділити на K ( x ) → шукаємо нульову остачу
  4. Розряд, який дав нуль — помилковий; виправляємо інверсією

⬡ Декодування Ріда-Соломона: 8 кроків

Алгоритмічна процедура корекції помилок:

  1. Обчислення синдромів s i = R ( α m 0 + i ) для 0 ≤ i ≤ 2 t − 1
  2. Якщо всі s i = 0 → помилок немає, кінець
  3. Сформувати поліном синдромів S ( z ) = s 0 + s 1 z + …
  4. Знайти Λ ( z ) та Ω ( z ) через ключове рівняння (Берлекемп-Мессі або Евклід)
  5. Пошук Чена: перевірити Λ ( α − j ) = 0 для всіх j → знайти позиції помилок
  6. Для кожної знайденої позиції обчислити значення помилки через процедуру Форні
  7. Сформувати поліном помилок E ( z )
  8. Корекція: C ̂ ( z ) = R ( z ) − E ( z ) (у GF(2): мінус = плюс = XOR)

⬡ Програмні моделювачі коректуючих кодів

Для дослідження властивостей завадостійких кодів існує клас програм-моделювачів:

  • RSCODE — моделювач Ріда-Соломона. Дозволяє задавати параметри коду ( n , k ) , кодувати файл data.txt у code.txt, спотворювати символи в кодованому файлі, виконувати декодування у decode.txt і порівнювати результати.
  • Бібліотеки в Python: reedsolo, pyfinite — для кодування/декодування РС, операцій у скінченних полях.
  • Бібліотеки в C/C++: Schifra, libcorrect — продакшн-якості реалізації РС, БЧХ, LDPC.

Експерименти з моделювачами дають інтуїтивне розуміння залежності кількості виправних помилок t від параметрів коду та поведінки декодера при кількості помилок понад t .
